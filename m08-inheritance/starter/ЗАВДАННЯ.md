# Модуль 8 — завдання

Теорія — у лекції «Модуль 08 — Наслідування». Список місць у коді: **View → Tool Windows → TODO**.

Ієрархія платежів: абстрактний `Payment` і два нащадки `CardPayment`, `SepaPayment`. Та сама ієрархія зроблена тричі — у трьох пакетах, по одному на стратегію. Кожна стратегія має свій persistence unit і свою схему бази, тому вони не заважають одна одній.

Колонки полів **уже описані** (`@Column` ми вивчили в модулі 2). Сьогодні додаємо лише анотації наслідування над класами.

## Обов'язкова частина

| № | Файл | Що додати |
|---|---|---|
| 1.1–1.4 | `common/BaseEntity` | `@MappedSuperclass`, `@Id` + `@GeneratedValue`, `@PrePersist`, `@PreUpdate` |
| 2 | `singletable/Payment` | `@Entity`, `@Table(name = "payments")`, `@Inheritance(SINGLE_TABLE)`, `@DiscriminatorColumn` |
| 3–4 | `singletable/CardPayment`, `SepaPayment` | `@Entity`, `@DiscriminatorValue("CARD" / "SEPA")` |
| 5 | `joined/Payment` | `@Entity`, `@Table(name = "payments")`, `@Inheritance(JOINED)` |
| 6–7 | `joined/CardPayment`, `SepaPayment` | `@Entity`, `@Table(...)`, `@PrimaryKeyJoinColumn(name = "payment_id")` |

Перевірка: `SingleTableTest` (після 1–4), `JoinedTest` (після 1, 5–7).

**Порівняння SQL:** запусти `Main` і порівняй для двох стратегій, скільки `insert` на один платіж і як виглядає `select p from Payment p`.
