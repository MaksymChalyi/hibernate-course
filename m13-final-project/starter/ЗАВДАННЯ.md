## Етап 1. Фільтри історії (модулі 6, 7) — 2–3 год

`GET /accounts/{id}/transactions` приймає необов'язкові параметри:

| Параметр | Приклад | Значення |
|---|---|---|
| `type` | `DEBIT` | Тип операції, без урахування регістру (`debit` теж) |
| `from` | `2026-01-01` | Дата за Києвом, включно |
| `to` | `2026-01-31` | Дата за Києвом, включно (весь день) |
| `minAmount`, `maxAmount` | `100`, `5000` | Межі суми, включно |

**1.1.** Створи `api/TransactionFilter`:

```java
public record TransactionFilter(TransactionType type, Instant from, Instant to,
                                BigDecimal minAmount, BigDecimal maxAmount) {
    public static TransactionFilter none() {
        return new TransactionFilter(null, null, null, null, null);
    }
}
```

`null` у полі = «умову не застосовувати». `from` — включно, `to` — **виключно** (так простіше з часом).

**1.2.** `AccountService.history(accountId, filter, page, size)` на Criteria API (модуль 7, завдання з динамічним фільтром):

- метод `conditions(cb, root, accountId, filter)` повертає `Predicate[]`: завжди `account.id = :id`, решта — лише якщо поле фільтра не `null`;
- запит сторінки: `cb.construct(TransactionDto.class, ...)`, `orderBy(desc createdAt, desc id)`, `setFirstResult` / `setMaxResults`;
- запит `count` — з **тими самими** умовами (інакше `total` збреше);
- старий `history(accountId, page, size)` викликає новий з `TransactionFilter.none()`.

**1.3.** `AccountServlet`: прочитати параметри і зібрати фільтр.

- `type`: `TransactionType.valueOf(value.toUpperCase())`;
- дати: `LocalDate.parse(value)` → `date.atStartOfDay(ZoneId.of("Europe/Kyiv")).toInstant()`;
  для `to` бери **наступний** день: `parseDate(to).plusDays(1)` — тоді `to=2026-01-31` включає весь день;
- суми: `new BigDecimal(value)`;
- будь-яке некоректне значення → `throw new IllegalArgumentException("...")` → 400 (уже працює з модуля 11).

**Готово, коли:** `curl.exe "http://localhost:8080/accounts/1/transactions?type=credit&from=2026-01-01&to=2026-12-31"` повертає 1 операцію; `?type=abc` → 400.

## Етап 2. Імпорт виписки (модулі 10, 11) — 2–3 год

`POST /statements`, тіло — CSV (`Content-Type: text/csv`):

```
account_number;booking_date;amount;currency;description
UA000001;2026-03-15;-1250.50;UAH;Оренда
```

**2.1.** Міграція `src/main/resources/db/migration/V3__statement_lines.sql`: послідовність `statement_line_seq` з `increment by 50`, таблиця `statement_lines` (колонки як у модулі 10), індекс `(account_number, booking_date)`. **V1 і V2 не змінювати.**

**2.2.** Entity `domain/StatementLine` (скопіюй з модуля 10, `SEQUENCE` з `allocationSize = 50`) + `<class>` у `persistence.xml`.
Додай статичний `StatementLine.parse(String line, long lineNumber)`: помилка розбору → `IllegalArgumentException("Рядок " + lineNumber + ": ...")`.

**2.3.** `persistence.xml`: `hibernate.jdbc.batch_size = 50`, `hibernate.order_inserts = true`.

**2.4.** `service/StatementImportService.importCsv(Reader csv)` → `ImportResultDto(rows, millis)`:

- **одна** транзакція на файл (`Tx.inTransaction`): помилка в будь-якому рядку → виняток → rollback усього файлу;
- перевір заголовок, порожні рядки пропускай;
- `flush()` + `clear()` кожні 50 рядків (модуль 10, завдання 3);
- додай сервіс у `AppContext` і створи його в `AppContextListener`.

**2.5.** `web/StatementServlet` (`doPost`): `request.setCharacterEncoding("UTF-8")`, далі `handle(response, 200, () -> app().statementImportService().importCsv(request.getReader()))`. Зареєструй у `AppServer` на `/statements`.

**Готово, коли:** `curl.exe -X POST http://localhost:8080/statements -H "Content-Type: text/csv" --data-binary "@statement.csv"` повертає `{"rows":...,"millis":...}`; файл з помилкою в рядку 5 → 400 з текстом «Рядок 5», у таблиці 0 рядків.
